# 时间织城 · 织梦巷与坎儿井

两关已经合并到这个项目：第一关「织梦巷」探索织坊、辨纹扎线和染绸；完成楼上观景处的回忆与收尾对话后，进入第二关「坎儿井」，制作绳梯和陶灯，完成清淤、修渠、复查和汇报。项目是纯前端静态页面，无需安装 npm 依赖或构建，通过本地 HTTP 服务运行。

第一关选择艾德或阿依苏，第二关自动沿用同一角色的原始 PNG 行走帧。第二关守井人使用独立的透明人物立绘，靴底贴合地面，视觉高度与主角一致。原来的「织梦巷_提交版」文件夹不需要参与运行，本项目已包含两关全部素材。

## 启动

需要 Python 3 和现代浏览器。在项目根目录执行：

```bash
python server.py 8080
```

然后打开 [游戏页面](http://localhost:8080/)，从关卡目录开始或继续旅程。Windows 也可双击 [启动游戏.bat](启动游戏.bat)；8080 端口已有服务时，启动脚本只打开页面（该服务需要指向本项目）。开发服务器禁用缓存，修改后刷新即可。

不要直接双击 `index.html`，浏览器会限制 `file://` 下的素材加载。

## 操作

第一关：`WASD` / 方向键移动，`E` / 回车互动；工作台使用鼠标，回忆画面可以点击跳过。顶部「关卡目录」保存当前进度并返回目录。通关后可继续探索或前往下一关。

第二关操作：

| 按键 | 作用 |
| --- | --- |
| `A` / `D` 或左右方向键 | 移动 |
| `E` | 互动、补完或推进对话；转盘工序中按住控制转速 |
| `F` | 井下开关油灯 |
| `Esc` | 退出制作、修渠或局部清淤作业 |

小游戏的鼠标、方向键和回车操作以当前界面提示为准。完整流程见 [当前游戏说明](docs/游戏说明.md)。

地表和井下均为贴地行走，移速为 240 逻辑单位/秒，不设跳跃。右上角只显示 `A/D 移动 · E 互动`，油灯与作业操作在相关场景内提示。

第二关的六处剧情转场使用与现有场景一致的手绘插画：抵达、下井、返井、中段疏通、下游复查和维护记录。首次上下井完整播放，再次往返缩短到 0.65 秒；其余画面每份存档显示一次。空格、回车、Esc 或右上角按钮可跳过，首次下井后仍需按 `F` 点灯。

第一关从地图进入时播放约 11 秒的分镜入场动画（`levels/weave-lane/intro/`），播完自动进入正片；动画页在嵌入式播放时隐藏「重播」按钮，由外壳调用 resume 开始、结束后交棒。地图入口对两关一致：进入时会清空该关进度并从头开始（第二关汇报后回地图、第一关随时返回地图都算一次新开局），关卡目录里第一关可接续原进度；第二关无论从地图还是目录进入都会重开。

第一关使用 DOM / Canvas，第二关使用 Phaser；统一入口每次只装载一个关卡 iframe，离开时先保存再销毁，防止全局常量、输入监听、音频与主循环相互干扰。两关通过共享服务接续角色和通关状态，角色图片只有一份。

第三口井的补缺口改为与第二口井清淤一致的现场作业：`A/D` 靠近亮点，`E` 观察、搬石、落石和压缝，最后站稳并按住 `E` 约 2.4 秒试水，再确认修补结果。`Esc` 暂停作业并保留已完成的步骤；未落位石料放回岸边。修补完成后仍需去下游参照石复查。

在两关内刷新页面都会继续当前进度。从地图进入时，两关都会从头开始：坎儿井重开任务、制作与转场，织梦巷清空本关位置、剧情、纹样与成绸进度并重播入场动画；已选角色保留。关卡目录里第一关可接续原进度；第二关无论从哪里进入都会重开。游戏画面不放置额外的重开按钮。

第二关最后的汇报对白结束、「水脉有记」转场播完后会自动收尾并回到入口：从小镇地图进入时回到小镇地图，从关卡目录进入或单独打开 `karez.html` 时回到关卡目录，不再弹出额外的完成界面。第一关仍保留“前往第二关”的衔接界面。

## 进度

- `twc_campaign_v1`：所选角色、当前关卡、关卡完成状态。
- `twc_l1_save`：第一关位置、剧情、纹样、扎线、拼纹、染色和成绸领取状态；每两秒及离开时保存。完成染绸但尚未领取时，继续旅程会重新打开领取画面；已经领取的作品不会重复发放。
- `twc_l2_save`：沿用第二关原来的 v4 存档与工作台进度；在井下退出会恢复到同一暗渠的井底落脚点，在地表退出则回到对应井口附近。
- 第二关的 `cutscenes` 字段记录已看过的转场；旧版 v4 存档可直接继续，不会为了补播画面重置任务。
- `weavelane.*`：保留第一关原有染谱草稿、作品册和设置。

同一浏览器、同一地址下，当前第二关页面刷新会继续存档，返回目录或地图后再次从入口进入则开始新一轮；不会把第一关标成已完成。浏览器或端口不同，存档不会自动互通。浏览器存储不可用时，统一入口在当前窗口内保留内存进度，目录会显示保存失败提示。

## 测试

安装支持 `node:test` 的 Node.js 后，在项目根目录执行：

```bash
node --test tests/*.test.cjs
```

测试覆盖绳梯装配与承重、和泥与拼接、转盘成型、烧制、制作进度恢复、布梯与重复下井的存档位置，以及跨关卡存档、旧存档兼容和完整的 190 张主角帧。

可选浏览器整合测试需要已安装 Chrome 和 Playwright。运行 `python server.py 8123` 后，在 PowerShell 执行：

```powershell
npm install --prefix tmp/browser-test --no-save --no-package-lock playwright
$env:NODE_PATH = "$PWD/tmp/browser-test/node_modules"
node tests/campaign.browser.cjs
```

该测试使用独立浏览器上下文，分别检查两位角色的选角、染绸领取前后退出与刷新、重复领取防护、制作中返回目录的实时存档、通关衔接、移动、下井、灯光朝向和井下恢复。部分制作里程碑使用仅存在于测试目录的状态快照，小游戏规则另由单元测试覆盖。截图输出到 `output/`，不会读写玩家日常浏览器存档。可用 `GAME_URL` 环境变量指定其他本地端口。

`tests/transitions.browser.cjs` 可单独检查六处转场的剧情顺序、原始人物分层、跳过、重复往返、存档和图片缺失时的继续操作，截图保存到 `output/transitions/`。该脚本的默认服务端口为 8243，也可通过 `GAME_URL` 指定。

`tests/patch-repair.browser.cjs` 检查两位角色的现场修补、照明与距离条件、搬运落石、压缝、试水暂停、刷新恢复及旧修渠工作台存档。默认使用 `http://127.0.0.1:5173/game/`，也可通过 `GAME_URL` 指定静态游戏目录；截图保存在 `output/patch-repair/`。

游戏运行页已移除剧情跳转、调试加速、素材校准和自动加载工具。旧的 `reset`、`ground`、`wells`、`tools` 参数不再修改进度或场景配置；关卡链接遵守正常解锁条件。美术参考稿和被正式角色图替代的试验图已从合并项目清理。

## 维护

- 新增第二关模块时，在 `karez.html` 按依赖顺序加入脚本；第一关模块在 `levels/weave-lane/index.html` 注册。修改脚本后递增对应的 `?v=N`。
- 修改场景或道具图片后递增 `js/main.js` 的 `ASSET_V`；UI 图片的缓存版本在 `js/UISkin.js` 中。
- UI 运行图片与当前用途见 [素材说明](docs/素材说明.md)。
- 临时截图、日志和一次性脚本放入 `output/` 或 `tmp/`，这些目录已忽略，无需随游戏分发。
- 文档描述当前实现。改动玩法后同步更新 [游戏说明](docs/游戏说明.md)，素材变更同步更新 [素材说明](docs/素材说明.md)。
